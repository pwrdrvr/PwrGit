# pwrgit-share

MIT, copyright 2026 PwrDrvr LLC. One Rust library and one CLI; no desktop packaging or auto-update integration.

From this directory, build with `cargo build --locked --release`. The pinned stable toolchain is Rust/Cargo 1.94.1. Install the resulting `target/release/pwrgit-share` on `PATH`, or configure PwrGit's `worktreeShareCommand`.

```sh
pwrgit-share probe --json /existing/destination/parent
pwrgit-share worktree add -b feature --seed-cargo --donor /repo --json -- /new/worktree HEAD
pwrgit-share cargo seed --from /repo/target --to /other/worktree/target --json
pwrgit-share measure --json /other/worktree
```

The library exports `probe`, `worktree_add`, `cargo_seed`, and `measure`, with serializable result structs. `Error.code` is the CLI exit code. `Options.force_no_cow` (or CLI environment `PWRGIT_SHARE_FORCE_NONE=1`) disables sharing for diagnostics and fallback tests. It cannot enable sharing.

Source materialization uses macOS `fclonefileat` (the descriptor form of `clonefile`) or Linux `FICLONE`. A real temporary-file clone and independent write in the destination parent establish capability. No-follow opens protect every donor path component. Git registers the worktree with `--no-checkout`; clean regular files with matching blob IDs and modes are cloned, hashed, entered into Git's stat cache, then Git completes checkout. Counts include only clones whose inodes survived checkout. Dirty, ignored, untracked, symlink, submodule, and unusual-mode files are left to Git. Unsupported/cross-filesystem source clones fall back to checkout. The CLI accepts `-b`; unknown flags and explicit `--detach` are errors. Existing branch arguments retain Git's normal branch semantics.

Target attributes come from the destination index before materialization. Paths with checkout conversion attributes (`text`, `eol`, `filter`, `ident`, `working-tree-encoding`, or legacy `crlf`) are conservatively left to Git, including explicitly unset attributes. Enabling `core.autocrlf` leaves all paths to Git. Every Git subprocess clears inherited repository-local overrides such as `GIT_DIR`, `GIT_WORK_TREE`, and `GIT_INDEX_FILE`. After materialization, Git runs `post-checkout` with ordinary worktree-add arguments in the destination, honoring `core.hooksPath`. Hook output is captured to preserve JSON stdout; hook failure returns exit 1 and removes this command's worktree and staging directories.

Cargo targets are separate directories. `--seed-cargo` clones only third-party units into the new worktree's `target/`: packages whose `cargo metadata` source is `registry+`, `sparse+` or `git+` **and** whose manifest lies under the recipient's resolved `CARGO_HOME` (`registry/src` or `git/checkouts`). The second condition matters because a vendored or directory-replaced source still reports `registry+`. Workspace, path, `[patch]`-to-path and vendored packages are never candidates. Neither are top-level outputs, `incremental/` or lock files. Each seeded unit is copied whole: the fingerprint directory, its `deps/` artifacts (rlib/rmeta, proc-macro dylib, `.d`, unpacked `.o`), and `build/<pkg>-<hash>` for build-script compile and run units. `worktree add` reports the result as a `cargo` object, or a `cargoSkipped` reason when it did not try. It seeds only a Cargo workspace at the repository root (`Cargo.toml` and `target/` side by side there); for a workspace in a subdirectory, run `cargo seed` on that workspace's target before its first build.

Every staged byte is scanned for the donor's root, which covers its target path. A unit that names the donor is rejected, along with its whole package. By fixed point, so is every package whose units were built against a rejected or unbuilt package, judged by the extern names in the unit's own fingerprint. In every mode, the allowed donor paths are those Cargo or rustc rewrite. A build script's `root-output` is its old OUT_DIR, and Cargo uses it to remap that OUT_DIR in `output`; the gate checks the recipient's link line for this. Rustc's `deps/*.d` may name the unit's own outputs and OUT_DIRs, and these are rewritten to the recipient's target. A proc-macro dylib may carry its own path as its macOS install name.

`--seed-cargo` defaults to **bounded** mode, which adds two exceptions for seeded artifacts only:

1. A donor path that is exactly `<donor target>/<profile>/build/<pkg>-<hash>/out[/...]` is allowed, provided that build-script run is seeded too. Its staged `out/` must also be verified at seed time to hold the same files and bytes as the donor's. Without that, the unit is rejected (`out-dir-not-seeded`) and the fixed point follows. This is the serde, serde_core and thiserror case: they `include!` generated OUT_DIR code, and their rlibs keep that path.
2. Mach-O debug-map strings (`N_OSO`, read from the symbol table) that point at donor `deps/` or the unit's own build dir are allowed, but only inside build-script and proc-macro executables. These run during the build and never reach a final binary.

Any other donor path is still rejected, including the donor workspace root and workspace or path packages' OUT_DIRs. **Residual effect of bounded mode:** for generated code in seeded third-party crates, backtraces, panic locations and debugger source paths point into the donor's target, including where that code is inlined into workspace crates (on PwrRoute, one panic-location string in gpui_base names html5ever's generated `rules.rs`). The content is identical while the donor exists. Generated code that opens its own `OUT_DIR` at runtime reads the donor's copy, and fails once the donor is gone; the gate demonstrates this. Reports count these units as `unitsSeededWithDonorOutDirPaths` and `unitsSeededWithDonorDebugMaps`. `--seed-cargo=strict` (`cargo seed --strict`) seeds none of them. Strict and bounded both run in the gate.

Seeding runs inside `worktree add`, holding nonblocking shared locks on every donor profile `.cargo-lock`, `.cargo-build-lock` and `.cargo-artifact-lock`. It stages privately and publishes with an atomic no-replace rename, so it never seeds into an existing target. Toolchain identity (`rustc -vV`, `cargo --version`) is read in both the recipient and the donor with `RUSTUP_TOOLCHAIN` cleared, so each directory's `rust-toolchain.toml` governs; the two must match. `RUSTFLAGS`, wrappers, `CARGO_BUILD_*`/`CARGO_TARGET_*`/`CARGO_PROFILE_*` overrides, Cargo configs that differ between the worktrees, configs that name either worktree, and configs that set rustflags, rustc, target/build dirs, `paths` or `[unstable]` are all skip reasons. Only exact `cargo --version` strings that passed `src/gate.rs` are enabled; every other version reports `fingerprint-unproven`. No public flag or environment variable bypasses that list. None of these conditions fails the worktree: it reports `unitsSeeded: 0` with a `reason` (`donor-busy`, `toolchain-mismatch`, `env-override`, `config-differs`, `metadata-unavailable`, ...). `copyCount` is always 0; `rewrittenCount` counts the regenerated `.d` files.

Staging uses private `<name>.<pid>.<sequence>.pwrgit-share-partial` directories. The final target is published using an atomic rename that refuses to replace an existing destination, including an empty directory. Failure/cancellation removes this process's partials and any worktree it registered. It never sweeps someone else's partials, prunes worktrees, runs `git gc`/`cargo clean`, or removes a donor/Cargo home. `SIGINT` and `SIGTERM` request cleanup at the next subprocess or file boundary; embedders can call `cancel()`. Git subprocess completion is awaited before cleanup.

All command results are JSON on stdout, including without `--json`; errors are JSON on stderr. Exit codes: 0 valid checkout or honest skipped seed (including a busy donor, reported as `donor-busy`), 1 I/O/checkout failure, 2 usage, 4 Git failure before materialization, 130 cancellation. A fallback exit 0 already created a valid worktree: callers must not create it again.

`measure.logicalBytes` sums regular-file lengths without following symlinks. Counts come from the initial operation record (the private Git admin directory for a worktree; a future enabled Cargo seed can use `.pwrgit-share.json`), with `countsOrigin` explaining that subsequent edits are not tracked. For other directories counts are 0/unknown. Counts describe clone operations, not surviving physical extent sizes. The current `measure` command labels APFS allocation `not-distinguishable` because it does not query clone attributes; neither `du` nor `st_blocks` proves sharing. On macOS, `scripts/apfs-audit.py` separately checks the same kernel attributes as DiskHound: clone ID, real volume identity, full-sharing flags, clone refcount, and private data bytes. Its `--self-test` includes a real clone, an ordinary-copy negative control, and a partial-write check. Use `--donor`, `--recipient`, and `--control` for disposable worktree comparisons. See the PwrRoute validation in [BENCHMARK.md](BENCHMARK.md). Free-space deltas in [BENCHMARK.md](BENCHMARK.md) are noisy.

Users may install sccache or Kache separately for compiler reuse. This tool never configures or spawns them, sets a wrapper, or edits global Cargo config. Smaller debug information and faster linkers are separate user choices.

Run `cargo test --locked`, `cargo fmt --check`, and `cargo clippy --locked --all-targets -- -D warnings`. Tests create disposable repositories and temporary Cargo homes. The freshness gate (`src/gate.rs`) builds a local registry inside its own `CARGO_HOME` and runs under `PWRGIT_SHARE_GATE_TOOLCHAINS` (default `1.97.1`). Registry units must be Fresh in the recipient with the donor's target hidden. Each negative fixture must recompile: `CARGO_MANIFEST_DIR`/`CARGO_BIN_EXE_*` tests, `include_str!` from outside the package, absolute `rerun-if-changed`, a registry rlib embedding a donor path and its dependent, and a vendored in-repo source. The recipient's test results must survive corrupting and then deleting the donor, and a late seed must leave every workspace unit compiling. The repeatable benchmark is `python3 scripts/benchmark.py target/release/pwrgit-share`; it uses vendored registry data and a local `file://` Git dependency, with no registry downloads. [BENCHMARK.md](BENCHMARK.md) records this machine's run and its limits.

[TESTING.md](TESTING.md) describes the generated property/model tests, their independent Git oracle, replay commands, and validation against the pre-fix implementation.
