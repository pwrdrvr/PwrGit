# pwrgit-share

MIT, copyright 2026 PwrDrvr LLC. One Rust library and one CLI; no desktop packaging or auto-update integration.

From this directory, build with `cargo build --locked --release`. The pinned stable toolchain is Rust/Cargo 1.94.1. Install the resulting `target/release/pwrgit-share` on `PATH`, or configure PwrGit's `worktreeShareCommand`.

```sh
pwrgit-share probe --json /existing/destination/parent
pwrgit-share worktree add -b feature --seed-target --donor /repo --json -- /new/worktree HEAD
pwrgit-share target seed --from /repo/target --to /other/worktree/target --json
pwrgit-share measure --json /other/worktree
```

The library exports `probe`, `worktree_add`, `target_seed`, and `measure`, with serializable result structs. `Error.code` is the CLI exit code. `Options.force_no_cow` (or CLI environment `PWRGIT_SHARE_FORCE_NONE=1`) disables sharing for diagnostics and fallback tests. It cannot enable sharing.

Source materialization uses macOS `fclonefileat` (the descriptor form of `clonefile`) or Linux `FICLONE`. A real temporary-file clone and independent write in the destination parent establish capability. No-follow opens protect every donor path component. Git registers the worktree with `--no-checkout`; clean regular files with matching blob IDs and modes are cloned, hashed, entered into Git's stat cache, then Git completes checkout. Counts include only clones whose inodes survived checkout. Dirty, ignored, untracked, symlink, submodule, and unusual-mode files are left to Git. Unsupported/cross-filesystem source clones fall back to checkout. The CLI accepts `-b`; unknown flags and explicit `--detach` are errors. Existing branch arguments retain Git's normal branch semantics.

Target attributes come from the destination index before materialization. Paths with checkout conversion attributes (`text`, `eol`, `filter`, `ident`, `working-tree-encoding`, or legacy `crlf`) are conservatively left to Git, including explicitly unset attributes. Enabling `core.autocrlf` leaves all paths to Git. Every Git subprocess clears inherited repository-local overrides such as `GIT_DIR`, `GIT_WORK_TREE`, and `GIT_INDEX_FILE`. After materialization, Git runs `post-checkout` with ordinary worktree-add arguments in the destination, honoring `core.hooksPath`. Hook output is captured to preserve JSON stdout; hook failure returns exit 1 and removes this command's worktree and staging directories.

Cargo targets are separate directories. `--seed-target` clones only third-party units into the new worktree's `target/`: packages whose `cargo metadata` source is `registry+`, `sparse+` or `git+` **and** whose manifest lies under the recipient's resolved `CARGO_HOME` (`registry/src` or `git/checkouts`). The second condition matters because a vendored or directory-replaced source still reports `registry+`. Workspace, path, `[patch]`-to-path and vendored packages are never candidates. Neither are top-level outputs, `incremental/` or lock files. Each seeded unit is copied whole: the fingerprint directory, its `deps/` artifacts (rlib/rmeta, proc-macro dylib, `.d`, unpacked `.o`), and `build/<pkg>-<hash>` for build-script compile and run units.

Every staged byte is scanned for the donor's root (which covers its target path). A unit that names the donor is rejected, along with its whole package and, by fixed point, every package that depends on a rejected or unbuilt one. The donor paths that are allowed are those Cargo or rustc rewrite, or that do not affect what Cargo builds. A build script's `root-output` is its old OUT_DIR, and Cargo uses it to remap that OUT_DIR in `output`; the gate checks the recipient's link line for this. Rustc's `deps/*.d` may name the unit's own outputs and its package's OUT_DIR, and these are rewritten to the recipient's target, which is the file a cold build writes. A proc-macro dylib may carry its own path as its macOS install name. Anything else is rejected, including registry crates that `include!` generated OUT_DIR code (serde, serde_core, thiserror and others), because that path ends up in their rlib and in code inlined downstream. Seeding runs inside `worktree add`, holding nonblocking shared locks on every donor profile `.cargo-lock`, `.cargo-build-lock` and `.cargo-artifact-lock`. It stages privately and publishes with an atomic no-replace rename, so it never seeds into an existing target. Toolchain identity (`rustc -vV`, `cargo --version`) is read in both the recipient and the donor with `RUSTUP_TOOLCHAIN` cleared, so each directory's `rust-toolchain.toml` governs; the two must match. `RUSTFLAGS`, wrappers, `CARGO_BUILD_*`/`CARGO_TARGET_*`/`CARGO_PROFILE_*` overrides, Cargo configs that differ between the worktrees, configs that name either worktree, and configs that set rustflags, rustc, target/build dirs, `paths` or `[unstable]` are all skip reasons. Only exact `cargo --version` strings that passed `src/gate.rs` are enabled; every other version reports `fingerprint-unproven`. No public flag or environment variable bypasses that list. None of these conditions fails the worktree: it reports `unitsSeeded: 0` with a `reason` (`donor-busy`, `toolchain-mismatch`, `env-override`, `config-differs`, `metadata-unavailable`, ...). `copyCount` is always 0; `rewrittenCount` counts the regenerated `.d` files.

Staging uses private `<name>.<pid>.<sequence>.pwrgit-share-partial` directories. The final target is published using an atomic rename that refuses to replace an existing destination, including an empty directory. Failure/cancellation removes this process's partials and any worktree it registered. It never sweeps someone else's partials, prunes worktrees, runs `git gc`/`cargo clean`, or removes a donor/Cargo home. `SIGINT` and `SIGTERM` request cleanup at the next subprocess or file boundary; embedders can call `cancel()`. Git subprocess completion is awaited before cleanup.

All command results are JSON on stdout, including without `--json`; errors are JSON on stderr. Exit codes: 0 valid checkout or honest skipped seed (including a busy donor, reported as `donor-busy`), 1 I/O/checkout failure, 2 usage, 4 Git failure before materialization, 130 cancellation. A fallback exit 0 already created a valid worktree: callers must not create it again.

`measure.logicalBytes` sums regular-file lengths without following symlinks. Counts come from the initial operation record (the private Git admin directory for a worktree; a future enabled target seed can use `.pwrgit-share.json`), with `countsOrigin` explaining that subsequent edits are not tracked. For other directories counts are 0/unknown. Counts describe clone operations, not surviving physical extent sizes. The current `measure` command labels APFS allocation `not-distinguishable` because it does not query clone attributes; neither `du` nor `st_blocks` proves sharing. On macOS, `scripts/apfs-audit.py` separately checks the same kernel attributes as DiskHound: clone ID, real volume identity, full-sharing flags, clone refcount, and private data bytes. Its `--self-test` includes a real clone, an ordinary-copy negative control, and a partial-write check. Use `--donor`, `--recipient`, and `--control` for disposable worktree comparisons. See the PwrRoute validation in [BENCHMARK.md](BENCHMARK.md). Free-space deltas in [BENCHMARK.md](BENCHMARK.md) are noisy.

Users may install sccache or Kache separately for compiler reuse. This tool never configures or spawns them, sets a wrapper, or edits global Cargo config. Smaller debug information and faster linkers are separate user choices.

Run `cargo test --locked`, `cargo fmt --check`, and `cargo clippy --locked --all-targets -- -D warnings`. Tests create disposable repositories and temporary Cargo homes. The freshness gate (`src/gate.rs`) builds a local registry inside its own `CARGO_HOME` and runs under `PWRGIT_SHARE_GATE_TOOLCHAINS` (default `1.97.1`). Registry units must be Fresh in the recipient with the donor's target hidden. Each negative fixture must recompile: `CARGO_MANIFEST_DIR`/`CARGO_BIN_EXE_*` tests, `include_str!` from outside the package, absolute `rerun-if-changed`, a registry rlib embedding a donor path and its dependent, and a vendored in-repo source. The recipient's test results must survive corrupting and then deleting the donor, and a late seed must leave every workspace unit compiling. The repeatable benchmark is `python3 scripts/benchmark.py target/release/pwrgit-share`; it uses vendored registry data and a local `file://` Git dependency, with no registry downloads. [BENCHMARK.md](BENCHMARK.md) records this machine's run and its limits.

[TESTING.md](TESTING.md) describes the generated property/model tests, their independent Git oracle, replay commands, and validation against the pre-fix implementation.
