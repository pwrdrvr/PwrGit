1 Findings — the run knows its size and never draws it

Sidebar › Try pull all and Fetch all repos open one dialog, BulkSyncDialog. It is told the repository count before the first Git command runs, and every remote:bulkSyncProgress event carries completedRepos and totalRepos. So progress is fully known at every moment — it just reaches the screen as a fraction and three chips. The specimen is the report's own state, 44 of 80 with three repositories in flight, reproduced at shipped size from app.css in the light theme it was reported in. Repository names are invented.

1bFour findings
1

The whole run is a fraction in a corner

44 / 80 is the only whole-run measure, set at 10 px mono in a pill. "More than half done" takes division, and nothing on screen grows as the run advances, so the dialog looks the same at 4 of 80 as at 76.

2

Three chips restate it in scheduler words

44 terminal · 3 in progress · 33 queued add up to 80, the same number again. "Terminal" is the engine's word for "finished, whatever happened"; every card below says success, partial or failed, and the chips never do.

3

A failure is only a red border somewhere below

Outcomes live in the list alone. When repository 12 fails, the strip above keeps saying Checking… in accent while a red card scrolls away. Whether the run is going well is a question the fold cannot answer.

4

No sense of time, and a line of filler

36 repositories left could take thirty seconds or five minutes; nothing says which. The second line of the strip is a sentence about the layout ("remains visible while results scroll below"). It shows up whenever more than one repository is in flight, and with a pool of three that is nearly always.

2 Three places a determinate bar can live

Same moment as 1a, dark theme. All three are determinate, because the total is known before the first repository starts, so there is never a reason to fake one with an indeterminate sweep. They differ in how much the bar is asked to say: only how far (2a), how far and how it's going (2b), or how far, how it's going, and where (2c).

5 What gets built — 2b, and the rules behind it

The build replaces the activity strip and the summary box with one component. It adds no IPC and changes nothing in main: every number already arrives on remote:bulkSyncProgress. Built alongside this artboard, in PwrGit#318.

RuleWhy
One card, two momentsThe .bulk-sync__status card is mounted for the whole run. At the end it trades the spinner for a mark, the clock for took, and the title for Finished or Cancelled, and the path line becomes the existing summary sentence, set as wrapping prose rather than as a path. The bar is never swapped out, so the receipt is the picture you just watched fill.
Segments are flex-grow = countflex-basis: 0 and flex-grow equal to the count, which is proportional by construction and animates. A non-empty outcome gets min-width: 3px, and flexbox takes that space from the others, so a single failure is never sub-pixel. Every segment is always mounted, so a count going from 0 to 1 animates instead of popping in.
Colors are tokenssuccess --status-ok, partial --status-warning, skipped the same warning mixed toward the panel, failed --danger-base (the base of the failed card's own border; --status-error sat too close to the light theme's warning brown), cancelled --status-suspended, in flight --accent striped. All exist in both theme blocks, so lint:colors and the theme contract need nothing new.
role="progressbar"aria-valuemax is the total, aria-valuenow the finished count, and aria-valuetext is "44 of 80 repositories finished, 1 failed". The legend is text, so no outcome depends on color alone.
The clock stays out of the live regionToday the whole strip is role="status" aria-atomic="true". A seconds counter inside it would be read out again every second. The live region shrinks to the title and path; the clock and legend sit outside it and can still be read on demand.
The clock ticks aloneThe one-second interval lives in its own small component that takes the finished count and total as props. The 80 repository cards do not re-render every second; they re-render only when a progress event lands, as they do today.
Estimate: 3 finished and 5 sRemaining is (total − finished) × elapsed ÷ finished. That is throughput, and it already accounts for the pool of three. It is rounded to 5 s under a minute and to whole minutes above, and always prefixed "about". There is no estimate while cancelling.
Reduced motionThe global prefers-reduced-motion rule stops the stripes and the width transitions. The in-flight segment is still an accent stripe, just static, so the state survives without the motion.
RemovedThe three terminal / in progress / queued chips (the legend and in flight · queued tail replace them) and the filler second line. The path line stays when exactly one repository is in flight.
