1Settings › General › Git runtime: a copy-on-write checkout switch that is always shown

PwrGit's own Git (the huntharo/git runtime, 2.56.0-dev-pwrgit.N) can write a worktree's unchanged files as copy-on-write clones of the main checkout. PwrGit turns that on by passing -c checkout.reflink=true to every Git it runs, while this switch is on and the Git in use supports it. The switch sits in the Git runtime card at all times. With any other Git it is drawn off and disabled, and its help line names the Git to switch to, with a Use that does it. Nothing is written to anyone's Git config. All data is invented.

2Maintenance › Clones: re-share every worktree’s unchanged files with its main checkout

A worktree loses its sharing whenever an ordinary Git, an editor or an agent rewrites its files, and a later checkout that changes nothing never gets it back. Refresh clones runs git worktree reflink on every linked worktree of every repository in scope: no Focused filter, no age guard. First it brings each main checkout up to its default branch, with Try pull’s rule (fetch, then fast-forward only a clean, tracked default branch), so more files match. Changed, untracked and ignored files are never touched; Git compares the bytes before it shares anything. Repositories run in parallel, with the same status card and receipt as the other tasks. The figure is Git’s own count of file data that stopped being private, which is not a promise of free space. All data is invented.

RuleDetail
Flag-c checkout.reflink=true before -C on every spawn, only while the switch is on and the Git in use answered --[no-]reflink in git worktree -h. Off passes nothing, so the reader's own config stays in charge.
ScopeEvery visible repository in the profile (or all profiles). Every linked worktree git lists; missing and locked ones are reported, never run.
Main checkoutTry pull's soft pull on the main checkout only, and only while it is on the default branch. Otherwise “left as it is” with the reason. A repository with no linked worktree fetches nothing.
LocksRepository lock for the repository, then each worktree's lock around its git worktree reflink --porcelain -z. Two worktrees per repository at a time; four repositories.
CancelCooperative. A running reflink is never killed; the queue stops.
FigureSum of the summary's observed-private-reduction. Words: “now shared”, never “freed”.
