1 Findings — six affordances, three busy languages, one bug

The reported screenshot shows three refresh controls on one screen, each animating differently. A sweep of apps/desktop/src/renderer/src finds three more. Every specimen below is reproduced at shipped size from the real CSS, in PwrGit's own font stacks, and is really animating — the third one is not a stylistic choice, it is a defect.

1bThe defect, and the three the screenshot missed
3

The box spins because there is nothing else to spin

.wt-refresh.is-refreshing svg targets the child glyph. Its sibling rule .ref-fetch-all.is-fetching has no svg — the button's only child is the text node ↻ — so the animation lands on the button element itself. One missing selector segment, and a bordered 24px box cartwheels.

11

Geist Mono has no U+21BB, so that glyph is a fallback

Measured in this document, in PwrGit's exact --font-mono stack: ↻ and a guaranteed-missing codepoint advance to the identical width, so nothing in the stack resolves it and the browser substitutes. The two mono buttons (.ref-fetch-all, .ref-mini-action) therefore draw whatever the OS supplies — different shape, weight and baseline per platform. .bulk-sync-action escapes it only because it is --font-sans, where the glyph does resolve. That is why the remotes control never quite matched anything near it.

4

Busy is orange in one place and grey in the other two

The ring is drawn from --accent. Both spinning glyphs inherit --text-muted / --text-subtle and never change colour, so "working" has no consistent hue.

5

Reduced motion removes the busy state entirely

app.css:97 kills every animation under prefers-reduced-motion: reduce. All three specimens then look identical to resting — the ring freezes as a broken circle, the glyphs just sit there. There is no non-motion fallback, so sighted reduced-motion users get no feedback at all that a fetch is running.

6

aria-busy is on two of the six

Only .wt-btn and .wt-refresh set it. The remotes buttons and the submodule refresh announce nothing, so a screen reader has neither the motion nor the state.

7

"Fetch all" names two different scopes

The sidebar's ↻ Fetch all fetches every repo in the profile. The remotes heading's ↻ fetches every remote in one repo. Same word, same glyph, two blast radii; only the second one says which in its aria-label.

8

Two of the six still blur focus mid-op

.wt-btn and the submodule refresh go disabled the instant they are pressed, so Chromium blurs them and a keyboard user is thrown to <body> (SC 2.4.3). This exact bug was already fixed on .wt-refresh and .ref-fetch-all with aria-disabled — the fix just never reached the other two.

12

None of the six has a keyboard shortcut

Fetch is the most-repeated action in the app and is reachable only by pointer or by tabbing to it. Out of scope here; noted so it is not lost.

7Sidebar top Sidebar · .bulk-sync-action
↻ Fetch all ↓ Try pull all

Text glyph again, inline with the label. No busy state of its own — it opens BulkSyncDialog, which owns the progress. That delegation is fine; the glyph and the name are not.

9Submodules rail SubmodulePanel · .submodule-panel__refresh
Refresh rest Checking… busy

A fourth vocabulary: no glyph at all, and the busy state is a word swap to "Checking…" — a verb used nowhere else in the app.

10Rebase tab RebaseTab · .rebase-head__icon
↻ The same ↻ character, decorative, labelling rebase. The one glyph the app uses for "fetch" also means "replay commits".

2 One busy language

Three treatments exist because nobody chose one. Two candidates below, then the part neither of them covers: what "busy" looks like when motion is off.

2aSpin the arrow, tint the button · recommended
Busy = accent tint + the glyph rotating in place
graph header Fetching…
headings Refresh

The glyph is a rotation, so rotating it is the literal reading — and unlike the ring it keeps the button's identity while it works: you can still see which control is busy. The tint is what does the heavy lifting; the spin is decoration on top of it.

Pull↓ and Push↑ keep the ring: their glyphs are not rotational, and spinning an arrow that means "down" is nonsense. That is the whole rule — the circular arrow spins; every other glyph swaps to the ring.

2bRing everywhere — one spinner, no exceptions
Busy = the glyph is replaced by the accent ring
graph header Fetching…
headings Refresh

Fewer rules — every busy control looks the same regardless of glyph, and .wt-btn needs no change at all. The cost: at 24px the ring nearly fills the button, the control loses its identity the moment it starts working, and a row of three busy headings becomes three anonymous circles.

Cheaper to ship, worse to read. Listed so the choice is on the record.

2cThe same three, with motion off — today vs. the proposal
5prefers-reduced-motion: reduce
today, busy ↻ indistinguishable from resting
2a, busy state survives without motion

This is the finding that outranks the cosmetic one. Because the tint is carried by [aria-busy="true"] rather than by the animation, it holds in both modes — and it makes a 13px busy signal legible for everyone, not only for users who asked for less motion.

Turn 3: one glyph or two?

3 The glyph, and the two verbs hiding behind it

Four of the six talk to a network (git fetch); two only re-read what is already on disk. That distinction is real and worth keeping legible — but the current encoding of it, a one-arc glyph versus a two-arc glyph at 13px, is not legible to anyone.

3aOne glyph, verb carried by name and placement · recommended
The two-arc arrow, everywhere, at 13px / 11px
Refresh

The text ↻ goes away entirely. Finding 11 is the clinching argument: the app's mono stack does not contain the codepoint, so today that button's shape is decided by the operating system. An inline SVG takes a stroke weight, matches its neighbours at 13px, renders identically on every platform — and gives the animation something to target, which is what fixes the box-spin.

Local-vs-network stays legible the way it already is in the code: by placement and accessible name. RepoRow.tsx:667 already argues this — the button sits under the Worktrees heading "where it can only read as re-list these". Placement was doing the work; the two-arc/one-arc split was never carrying it.

3bTwo glyphs — keep a visual split between network and local
At the size these actually ship
network one arc · fetch
local two arcs · re-read

This is what ships today, minus the text glyph. Side by side and called out, the difference is findable. In the app they are never side by side — they are 400px apart in different panels, one per panel, at 13px. Nobody decodes that.

Keep it only if we also give the local one a genuinely different shape. Two arcs vs. one is a distinction that exists in the source, not on the screen.

4cJudgement calls worth a second opinion before they ship
A

Dropping the network/local glyph split

3a retires a distinction the code deliberately encodes. The argument for retiring it is that 13px one-arc vs two-arc never conveyed it and placement always did. If we would rather keep a visual split, it needs a genuinely different shape, not a second arc — that is a bigger change than this pass.

B

Changing the graph header Fetch from ring to spin

It is the most-used button of the six and the only one whose busy state is currently good. Swapping it is for consistency, not because it is broken. Leaving it on the ring is defensible — it just means the toolbar and the headings keep speaking differently.

C

The RebaseTab ↻

Decorative, not a button, and outside the refresh family — but it is the same character meaning something else, and it inherits the same missing-codepoint problem. Changing it is scope creep for this PR; flagging it so it is a choice rather than an oversight.

D

Not controversial: the box-spin, the tint, and aria-busy

The cartwheel is a defect, the reduced-motion gap is a real accessibility hole, the mono ↻ is an unrendered codepoint, and the missing aria-busy / aria-disabled are repeats of fixes this codebase has already made twice. Those ship regardless of A–C.
