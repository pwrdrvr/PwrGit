1bSix findings
1

It reviews titles, not code

The request carries hashes and subjects, nothing else (promptFor in agent-session.ts). No diffs are sent, so every rationale and risk is a guess from commit titles.

2

A verdict with nothing behind it

“High confidence · Proceed” comes from a model that saw no code, and it shows up above the isolated check, the one signal that actually knows whether this works.

3

It can only agree

Every step has to match PwrGit's canonical plan exactly or the response is discarded. The rationale can only restate the selection. Nothing the agent writes changes the outcome.

4

It skips the one job a squash needs

The squashed commit's message is still Git's list of subjects. The agent even flags “the combined message may need editing”. Writing that message is the most useful thing it could do here.

It's Codex or nothing, at whatever version discovery found. There's no provider, model or effort choice and no settings page. Claude Code and other ACP agents are detected and then refused.

2 The boundary that lets the agent write the plan

#149's safety rule is “the agent must copy PwrGit's plan”, and that rule is exactly what stops it helping. The property that matters is weaker, and PwrGit can prove it: whatever the agent proposes must leave the code byte-for-byte identical and must replay cleanly. PwrGit checks both before a plan can be applied, so the agent is free to propose instead of just review.
