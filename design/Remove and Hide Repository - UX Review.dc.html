1The two new entries on the repository row, and what Hide does with no dialog

Both entries go last on the repo row’s menu (RepoRow.tsx menuItems()), below a separator, in the order least to most consequential: Hide, then Remove. Remove uses the existing danger item style. Hide gets no ellipsis and no confirmation: it changes nothing on disk, so the cost of a mistake is one click, and the info toast carries Undo. Remove keeps the ellipsis because it opens a review. All repository and branch names on this page are contrived.

1dWhat Hide means, decided
QuestionDecision
ScopePer profile. Hiding in Work does not hide in Personal, even when both scan the same folder.
What is hiddenThe repository, keyed by its main checkout’s path in that profile. Every worktree of it goes with it, including a linked worktree a scan finds in another registered folder, because worktrees are grouped under their main checkout. The key outlives rescans, which delete and recreate repository rows. A worktree cannot be hidden on its own; that is what pinning and the Focused lens are for.
RescansA hidden repository is still discovered (so Settings can say whether it still exists), then filtered before it reaches the renderer. It never comes back by itself.
Background workNone. No status polling, no fetch, no forge identity or PR refresh, no index of its commits for search. Unhide schedules one refresh.
Current repositorySelection moves to the next visible repository (see 1c). Back/Forward skips history entries in a hidden repository.
Agents (MCP)Left out of the app catalog: repositories, recent repositories, search. Opening one by path answers “hidden in this PwrGit profile” rather than pretending it does not exist, so an agent does not go and re-clone it. Tools that take a path and read the folder directly still work; hiding is about PwrGit’s lists, not about the files.
Removed folderIf a hidden repository disappears from disk, its entry stays in the hidden list marked Not found, with Forget. Nothing prunes it silently.

2Remove repository: one review dialog, every checkout listed, worktrees first

The dialog opens on a scan of every checkout: each linked worktree, then the main checkout last, because the main checkout holds .git and so carries the repository-wide things that die with it (stashes, local branches nothing has checked out). Each row gets a verdict. Safe needs nothing. At risk needs an explicit choice: Push first, Keep, or Discard; there is no default. Blocked (an operation in progress, a locked worktree, a running PwrGit operation) offers only Keep or a way to go fix it. The button stays disabled until nothing is undecided or blocked. Folders go to the Trash; permanent deletion only ever happens as its own named step.

2gWhat the scan checks, and what each finding allows
FindingVerdictChoices, and why
Uncommitted or untracked filesat riskKeep or Discard. Push first is offered only when unpushed commits are the only risk on that checkout. Ignored files are not work and are not counted, but their size is.
Commits on no remoteat riskPush first, Keep, Discard. Measured as commits reachable from the branch and from no remote-tracking ref, so a branch with no upstream and a branch ahead of its upstream read the same way.
Stashesat riskKeep or Discard, on the main checkout: stashes live in .git.
Local branch, not checked out, on no remoteat riskPush first, Keep, Discard, on the main checkout.
Rebase, merge, cherry-pick, revert or bisect in progressblockedKeep, or Open worktree to finish it. Never discarded from here.
Locked worktreeblockedKeep. Someone locked it on purpose; unlock it first.
A PwrGit operation is running in itblockedWait. The row unblocks itself when the pull, fetch or commit ends.
Worktree folder not foundat riskKeep or Discard. It may be on an unmounted volume, so absence is not proof it is gone. Discard clears that worktree’s record only; nothing here runs a repo-wide git worktree prune.
Submodules with their own unpushed workat riskListed as a fact on the checkout that contains them; same choices as uncommitted files.
Trash unavailable—Network volume, or Linux with no trash. Known before the run: the row says so, the button becomes Delete permanently, and the name gate applies whatever the other choices are.
Profiles—The repository leaves every profile’s index, since the folders are gone. A profile with it hidden keeps a Not found entry (1d).

3Seeing and unhiding hidden repositories

Three surfaces, each for a different moment. The sidebar footer is where you notice (it only exists while something is hidden). Settings → Profiles is where you manage every profile’s list. The palette catches the “where did it go” search without putting hidden repositories back into ordinary results. Recommendation: 3a and 3b, with 3c as the safety net.
