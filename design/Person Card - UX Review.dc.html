What it costs

Two new calls per person — GET /users/:login for name and company, GET /users/:login/orgs for orgs — plus a cache table and org-avatar thumbnails beside the author ones.

Orgs are mostly empty. The API lists public memberships only, and membership is private by default. For most colleagues the row would read “none”, or have to be hidden — a section that is usually a blank is noise.

The profile name repeats the Git name in the common case, and when it differs the card has two names to explain.

What it adds

A graph filter keyed on author email, shown as a removable chip in the Lineage header so the filtered state can’t be forgotten. It sits inside “In this graph” because that is what it acts on; the bottom row stays about the person.

The hard part is the lanes, not the card. Hiding rows breaks the ribbon between the ones left. Folding them to a hairline keeps every lane continuous — a decision worth its own turn.

Prior art: the graph shipped with an “Only me” default, retired when multi-lane lineage replaced it. This is the same idea, for anyone, on request.

Reading the set

The status line is the one that varies. Photo, login and the GitHub button appear together or not at all — never a login without the proof behind it. Before the store’s first visit it reads “Not checked with GitHub yet”, muted, in the same slot.

GitLab proves authors too (GraphQL commit.author), so a GitLab card looks like the GitHub one with “Open on GitLab”. GitCafe is the forge that cannot.

Your own card drops the co-author line (you don’t co-author yourself). The eyebrow says it is yours: the row’s “you” comes from the profile’s commit email.

A blank Git name reads “Unknown author” with “?” initials, as the commit card already does.

2cQuestions for the operator
1

Count by email or by account?

One person, two emails (work laptop, home laptop) is common. By email, the card undercounts them; by proven login, it merges them — but only for commits that are proven. Built by email, for now.

2

Does the SHA card keep its identity block?

It is about the commit, so keeping the author there is fair. The alternative is a single line there that opens this card.

3

Is “Open on GitHub” worth a network hop?

Answered in the build: main builds the link from the proven login and the proof’s own forge origin, with no API call, so an Enterprise or self-managed GitLab host keeps its own address.
