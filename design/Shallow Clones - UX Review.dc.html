Brief: limited-history (shallow) clones

A shallow clone downloads only the newest commits of each branch instead of the project's whole history. It saves download time and object-database space on long-lived repositories; it does not make the checked-out files any smaller. The cost: history, blame and file history stop at the boundary, a merge or rebase whose common ancestor is older than the boundary cannot find it, and a later deepen does not fetch tags on the older commits it brings. Before this round PwrGit always cloned full history and showed a shallow repository (made elsewhere) as if its oldest downloaded commit were the project's first. Goals: an opt-in at clone time, a truthful boundary in History, and one explicit, cancellable way to fetch more. Full history stays the default.

Clone dialog: one opt-in row, not a bag of flags

Placed under “Clone with”, styled as the existing upstream option row. It is drawn at open and never depends on the forge, so it cannot move anything after the pick. The commit count is inline in the row, so turning it on does not change the row's height. Depth is a whole number 1–100,000; anything else disables Clone with the reason in the row.

1b On: the count appears inline, with what it costs

Main runs git clone --depth 50 --no-single-branch. Without --no-single-branch Git would fetch only the default branch and rewrite the fetch refspec, and every other branch would silently disappear from PwrGit. With it, every branch and every tag arrives with its own newest N commits, so a project with many old tags still downloads history near each one.

1c Invalid count

Main validates again: the renderer is not the boundary.

1d Sources that change the meaning

Local path. Git ignores --depth for a plain path (it hard-links objects instead), so PwrGit clones from the path's file:// URL. The row says so: “Copies through Git's file:// transport, so objects are not hard-linked.”

GitHub / GitLab CLI. Passed to Git after --. GitCafe CLI cannot pass Git options: with that card chosen the row is disabled with “Not available with the GitCafe CLI. Choose SSH or HTTPS.” Nothing silently falls back to a full download.

Server refuses. A server without shallow support (e.g. dumb HTTP) fails the clone; the error says the server can't make a limited-history clone and to clear the box for a full clone. No automatic retry as full.

Fork… / Clone from your fork. Not in this round; that path keeps full history.

History: show where downloaded history ends

Git pretends a shallow boundary commit is a root. PwrGit marks it instead: the lane ends in a dashed cut, the row carries a history cut chip, and a note under the graph offers the one fix. Read cost: one rev-parse and the shallow file per load; no network and nothing deepened while browsing.

Fetching more: an ordinary remote activity

Both buttons run one tracked fetch (git fetch --progress --deepen=100 origin or --unshallow), so the activity popover shows progress and Stop like any fetch. The buttons disable while it runs. Nothing deepens on its own: browsing History never fetches.
