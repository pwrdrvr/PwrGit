1As built — “merged 14 days ago” is a rule you can read but not change

A worktree counts as finished when its pull request merged (any age), or when its branch is merged into the default branch and has had no commits for 14 days. The 14 is the constant STALE_AGE_DAYS, shared by the sidebar’s Stale lens and the sweep. Someone who merges and wants the checkout gone today has no way to say so. The recent-activity guard can be switched off, but it resets to 7 days every time the dialog opens.

The 14 days is fixed

No control anywhere changes it. The Worktrees tab states it in a grey “Finished means merged” card; the review strip says merged 14 days ago. The wording is also off: the clock is the branch’s last commit, not when it merged.

2

The guard forgets

Unchecking “Keep worktrees touched…” works for one run only. Branch rules beside it are saved; this one resets to 7 days on every open.

2Proposed — a second rule under step 1, saved like the branch rules

One new select, Count a branch merged into the default branch as finished: right away, 1, 3, 7, 14 (default) or 30 days without commits. Both worktree rules are saved in settings and come back on the next open. The sidebar’s Stale lens reads the same setting, so the lens and the sweep still agree. A merged pull request stays finished at any age. Worktrees that share no history with the default branch keep the fixed 14 days: nothing proves they merged.
