3Adopting one tag — explicit, recoverable, and only that tag

The two writes PwrGit makes are both per tag and both asked for. Take origin’s fetches +refs/tags/<name> with --no-tags into a staging ref, checks it is the value the user reviewed, then swaps refs/tags/<name> with a compare-and-swap. The old object is pinned first under refs/pwrgit/replaced-tags/, a real Git ref, so gc keeps it and Restore can put it back. Keep local writes nothing to Git: it records the pair of values, and the row stops asking until either side moves again.

1Findings — a moved tag is invisible today, and forcing every fetch is the wrong fix

A maintainer re-cut v1.2.3 on origin. Fetch and Pull skip a tag name that already exists, so the local tag kept its old commit, and nothing on screen said so. The first version of PR #549 added --tags --force to every fetch. That also overrides tagOpt=--no-tags, downloads every tag-only history, and lets whichever remote is fetched last decide what a shared tag name means. This review replaces it with a published source that is read, compared and adopted one tag at a time.
