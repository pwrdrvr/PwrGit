0 The ask, the gap, and what to check

Operator: “This dialog doesn’t have Clones as a step that users can check (and it should be on by default). AND we should be doing a quick background scan once and giving the user a toast that they can run this sweep, it’s fully compatible with other git consumers and tools, and it will save X projected GB of disk for them (if possible to tell from the sweep). If they click ok we should run the maintenance tool with ONLY clones selected.”

The gap. Clones (git worktree reflink, Refresh Clones turn 2) exists only as its own tab. Combined, the tab people use, runs Repair → Worktrees → Local branches → Garbage collection and never shares files. Nothing tells a user the sweep exists or what it would get them. Rooted in Maintenance Combined turn 3 (step cards, pause tags, rail, per-step receipt) and the house toast (app-toast, PwrAgnt’s AppNoticeToast).

Can the number be honest? Yes. PwrGit’s Git has git worktree reflink -n, a dry run whose porcelain summary carries potential-private-reduction. On a scratch repository (20 × 1 MB files, one edited) the dry run projected 19,070,976 bytes; the real run then reported observed-private-reduction 19,070,976. The edited file was left out of both. A dry run took 0.05–0.15 s per worktree across 40 real worktrees, so the scan is cheap.

  1. Order: Repair → Worktrees → Local branches → Clones → Garbage collection. Worktree removal goes first, so no time is spent sharing files in a checkout about to be deleted. Branch deletion touches no working files, so it doesn’t matter whether it comes before or after. Clones runs before GC because its “Update main checkouts first” fetches, and GC then packs what the fetch brought. GC never touches working-tree files, so it can’t undo the sharing.
  2. Tag: “No pause”. Clones never stops for review.
  3. The rule “Update main checkouts first” comes with it, on by default, as on the Clones tab.
  4. Once per profile. The scan runs once the profile has a linked worktree and the Git in use can re-share. Its outcome is stored. If a toast was shown, it never comes back, whether it was accepted, dismissed, or still open when the app quit.
  5. A number only when Git measured one. If some worktrees couldn’t be measured, the toast says “at least”. If none could be, it gives no number.

Open questions. (a) Threshold for “meaningful”: 512 MiB projected. Higher? (b) Units follow the Clones receipt (GiB). Switch both to GB? (c) The operator asked for “save X GB”. The house rule says never “freed” (Time Machine keeps blocks). The toast says “could save about X”, labels it projected, and the receipt keeps “now shared”. OK?

1 Combined plan: Clones becomes step 4, on by default

One card in the existing anatomy: checkbox, number, title, a No pause tag in the style of Repair and GC, one sentence, and its one rule. GC moves to 5 and keeps “Runs last, no pause”. The footer lead counts pauses the same way. Clones never pauses, so it adds none.

4 Build notes
  1. Plan: MaintenancePlan gains clones (default true). Combined runs { kind: "reshare", updateMain } between branches and GC. The receipt’s line comes from clonesHeadline, the Clones tab’s own, worded “now shared”.
  2. Estimate: maintenance:estimateClones in main runs git worktree reflink -n --porcelain -z per linked worktree. It sums potential-private-reduction where the worktree reported allocation, and counts eligible files. A pure fold (clonesEstimate), property-tested.
  3. Once: a per-profile record in SQLite (profile_notices). The pure decision (clonesOfferStep) is held by a model test: at most one toast per profile, across any sequence of launches, scan outcomes and answers.
  4. Accept: the Sidebar opens the dialog with initialPlan = only Clones and autoStart. A test asserts the plan holds exactly clones.
