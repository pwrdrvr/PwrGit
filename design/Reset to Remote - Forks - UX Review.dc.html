3

"Upstream" means two different things

The tag on origin/main uses Git's meaning: the branch this one tracks. On a fork, the remote named upstream is the source. The card labelled UPSTREAM is the one that is not.

4

"Moments ago" described origin only

The fork is left behind

Resetting main to the source leaves origin/main where it was. Updating the fork is a second, separate operation, and a forced one when the fork has commits of its own.

3 Confirm — the push is part of the plan, not an afterthought

The review step keeps its ledger and adds one block: exactly what will be pushed, where, and what the lease expects to find there. The push runs only after the reset succeeds. It pushes the object the review showed, not whatever main points at by then, and its lease is the origin/main tip this dialog read.

The acknowledgement already exists for a hard reset that strands commits. A ticked force-push now requires it too, in either mode: a soft reset keeps the changes locally, but the push still deletes the commits from the fork.

Soft reset with a fast-forward push, the everyday fork sync, stays exactly two clicks from opening the dialog: Review, then Soft reset + push.

4 Outcome — one receipt, and a push failure never undoes the reset

The reset and the push are two Git operations, so the dialog reports them as two facts. If the push fails after the reset has landed, the toast says so and names what to do next. It never reads as though the whole thing failed.
