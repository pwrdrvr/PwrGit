1 Findings — Git can already pick an identity by folder; PwrGit profiles already own folders

Round 1 (Commit Identity and Signing, PR #448) made PwrGit’s own commits honest and gave Git one machine-wide identity. People with a Work and a Personal profile need more: Terminal and coding agents in ~/Work should commit as the Work email. Git does this with a conditional include. An [includeIf "gitdir:~/Work/"] in ~/.gitconfig pulls in a second file for every repository under that folder. A PwrGit profile already lists the folders its repos live in. So the easy mode is: one switch, and PwrGit writes and maintains an include per profile folder. Every probe below ran against an isolated HOME with GIT_CONFIG_NOSYSTEM=1 and Git 2.56. Identities are contrived.

1aWhat the probes say
✓

An included file reports scope global and names itself as the origin

So PwrGit can tell its own include from the user’s hand-written one, and from ~/.gitconfig itself, with the --show-origin --show-scope read round 1 already does.

$ git -C ~/Work/api config --show-origin --show-scope --get-regexp '^user\.'global  file:~/.gitconfig                user.email rowan@vale.exampleglobal  file:~/.gitconfig-pwrgit-work   user.email rowan@northwind.example
1

Order decides: a [user] written after the include wins

The include only overrides what comes before it in the file. git config --global user.email edits an existing [user] in place, but appends one when there was none, which lands it after PwrGit’s includes and silently undoes them. So PwrGit re-appends its includes at the end of the file on every sync, and checks the result.

~/.gitconfig, in file order:[includeIf "gitdir/i:~/Work/"]  path = ~/.gitconfig-pwrgit-work[user]  email = rowan@vale.example   # appended later$ git -C ~/Work/api config --get user.emailrowan@vale.example
2

The folder itself is not a repository, so it can’t be asked

gitdir: matches a repository’s .git location. git -C ~/Work config outside any repo ignores the include. The only honest answer is per repository: ask each indexed repo, one git config process each, bounded.

✓

Linked worktrees follow their main repository

A worktree’s gitdir is <main>/.git/worktrees/<name>, so a checkout at ~/Elsewhere/wt of a repo under ~/Work still gets the Work email. That matches PwrGit, which files worktrees under their repo.

3

A repository’s own user.email beats every include

.git/config is scope local, read after global. A repo someone pinned by hand keeps its email, and only the per-repo read can find it. That is the “differs” case the review lists, with a one-click, previewed removal.

4

Two profiles sharing a folder already make a mess

repos.path is unique, and the indexer’s upsert reassigns profile_id on every scan. A repo under both profiles’ roots moves to whichever profile scanned last. Nested includes would also fight: the later one wins. Refuse a root that equals, contains or sits inside another profile’s root, and flag the ones that already do.

5

macOS and Windows need gitdir/i:

Case-insensitive file systems hand Git paths in whatever case they were typed. gitdir/i:/Users/rowan/work/ matched ~/Work/api. Linux keeps plain gitdir:. A missing include file is skipped silently, so the read after a write is the only check that it took.

3 Settings › Profiles › By folder — one switch, every profile’s folders, and the repos that disagree

A second card under round 1’s “Git identity”. Off by default, and turning it on writes nothing until the preview (4a) is confirmed. While it is on, PwrGit rewrites its includes whenever a profile’s email, author name or folders change, and the profile editor says so (4c). That is the disclosed, opted-in exception to “never change Git config silently”. Repos that still disagree are listed per profile, with the file that wins.

4 Every write is previewed — turning it on, removing an override, and the profile editor

Same rule as round 1’s set-up dialog: name the file, show the lines, write at a click, then ask Git again and report a write that did not take. Turning the switch off removes PwrGit’s includes and files (also previewed); a user’s own includes are never touched.

4aTurn on — the exact lines

Match Git to each profile

Repositories under a profile’s folders will commit as that profile, in Terminal, scripts and coding agents too. Existing commits don’t change. Repos that set their own email keep it.

~/.gitconfig — appended at the end, so they win over [user]
[user] … unchanged
+ [includeIf "gitdir/i:/Users/rowan/Code/"]
+ path = /Users/rowan/.gitconfig-pwrgit-personal
+ [includeIf "gitdir/i:/Users/rowan/Work/"]
+ path = /Users/rowan/.gitconfig-pwrgit-work
~/.gitconfig-pwrgit-work — new
# Written by PwrGit for the “Work” profile. Edit the profile instead.
+ [user]
+ email = rowan@northwind.example

Plus ~/.gitconfig-pwrgit-personal with rowan@vale.example. A profile without an author name keeps Git’s user.name. While this is on, PwrGit rewrites these when you edit a profile’s email, name or folders.

4bRemove a repo’s own email

Remove infra-live’s own email?

This repository sets user.email = rowan@vale.example in its .git/config, which wins over the Work profile’s folder identity.

~/Work/infra-live/.git/config
[user]
- email = rowan@vale.example

Afterwards it commits as rowan@northwind.example. Same as git -C ~/Work/infra-live config --local --unset user.email.

Overlap rule: a root is refused when it equals, contains or sits inside another profile’s root. Only roots being added are checked, so a profile that already overlaps can still be saved while it is untangled; the card and the popup keep flagging it. Comparison is on resolved absolute paths, case-folded on macOS and Windows.
