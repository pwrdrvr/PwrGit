1Findings — each row sizes its own actions column, and branches cannot be pinned

The reported symptom: in the refs browser a branch row is out of line with the rows around it, and there is no star on a branch. The first is a layout bug with a design cause: too many peer buttons in a column sized by its content. The second is a missing verb. Because the cause of the first is shared, the frames below check all four tabs before proposing anything.

1b-findWhat is wrong
1

Every row is its own grid, and the actions column is auto

A local row that is not checked out carries four buttons, so its actions column resolves to 283 px. Remote and checked-out rows resolve to the 210 px minimum. The extra 73 px comes out of Upstream: on main and fix-local-rewrites, origin/… starts 43 px left of the UPSTREAM header and of the rows around it (measured at 940 px). The header and each row resolve minmax(210px, auto) separately, so nothing holds them together.

The stylesheet comment says the actions column “matches the branch table’s so Switch here sits in the same place on both tabs.” It only holds while both tables have the same number of buttons.

2

Four verbs at one weight, two of them rare

Switch here is the accented default and New worktree is second. Rename and Delete are used a few times a year, and Delete is the one that can lose work. It sits six pixels from Rename, in the row you are most likely to be reaching into for Switch here. Both are also the two buttons that go disabled on a checked-out branch, so a row swaps which of its buttons are dead.

3

No way to pin a branch here, and none from ⌘K either

The refs browser has no pin control. The pin verbs that exist are worktree:setPin and repo:setPin, so a branch with no worktree, like main when the primary checkout sits on another branch, has nothing to pin. ⌘K hides its pin button for exactly those rows (hasNoCheckout).

3Pinning a branch — where the control goes, and what a pin is

The app already has one pin: the five-point star (PinIcon) on worktree rows, ⌘P in ⌘K, and the sidebar’s Pinned group. The request is to reach it from a branch row. The catch is that a pin today is attached to a worktree or a repo, so a branch with no worktree has nothing to attach it to. 3c and 3d draw what that costs.

6What changes, and what is left open

6bOpen questions
?

Rename a pinned branch: does the pin follow?

It should. Rename already refuses a checked-out branch, so the pinned branch is always the one with no worktree. That keeps the rule simple: rename moves the pin.

?

Delete a pinned branch

Deleting a pinned branch should not leave a ghost row in the sidebar. It can unpin, and say so in the confirm dialog that already lists what will be lost.

?

Star or pin?

The glyph is a star and the sidebar, tooltip and shortcut all say pin. This artboard keeps pin everywhere so there is one word, and leaves the star on repository rows as it is.
