1

No count anywhere on the toolbar

The run’s progress is folded inside BulkSyncDialog (it subscribes to remote:bulkSyncProgress itself). useBulkSyncRun only knows busy, so the face, its card and the menu can say “running” but never “12 of 27”. A hidden timed run has no mounted view at all.

2

The card says “click” but is a tooltip

“Click to watch” sits in a hover card you cannot click, so the eye goes to the card and finds nothing to press. It also restates the setup (27 repos, every 5 minutes) instead of the run’s state.

3

The click opens the remembered view, not the dialog

nextBulkSyncRun reveals a hidden run in readBulkSyncView(), which is toast for anyone who has minimised once. Then a second click on a run already in a toast returns it unchanged, so the button does nothing. Only Sync options → Show the running sync forces the dialog.

4

The menu entry has no hint

“Show the running sync” is the one sure way in, and it gives no position or clock, while Show last run does (lastRunHint).

5

Busy looks the same at 1 of 27 and 26 of 27

The ring spins at the same rate throughout. Whether to wait or move on is the one thing a busy face could answer, and it doesn’t.

3Hover shows the run; click opens it

While a run is live, the hover card stops describing the setup and draws the run, using the same BulkSyncStatus parts the toast uses. The setup text comes back when nothing is running.

Show the running sync gets a hint

Same shape as Show last run’s: position, trouble, then automatic and the clock.

✓

Lift the fold out of the dialog

useBulkSyncRun subscribes to remote:bulkSyncProgress for the live run and folds it once (the same fold the dialog uses today). Face, hover card, menu hint, toast and dialog all read that one value, so they can’t disagree. The dialog stops subscribing on its own; this also gives a hidden timed run a progress value while nothing is mounted.

✓

A test that fails today

Rule 7: a model test where a run starts hidden, events arrive in any order, and the view switches hidden → toast → dialog at random points. It asserts that every surface shows the same finished/total as a fold of all the events. Add a second rule: clicking the face on a live run always ends in dialog. That fails on the current nextBulkSyncRun.
