1 Settings › Updates — the four-slot release matrix

As built. Two trains (rows) × two tracks (columns), all four published slots on screen at once. Every tile states its own resolved version whether or not it is the selected one, an empty tile says why it is empty, and a tile click writes both axes in one settings:update patch. The matrix is a roving-tabindex radiogroup: arrow keys move focus without changing the feed, which commits on Space/Enter or a click.

The pin is a third field, not a shape. updates.selectionSource is main-owned: while it reads "inferred", train/track are re-derived from the running binary on every hydration, so a hand-installed alpha follows the alpha feed. The write path derives "user" from any patch naming either axis, and the patch allowlist drops the field — a renderer can neither pin a selection nobody clicked nor un-pin one that was. Without it, stable/latest on disk is equally “the default nobody touched” and “the choice somebody made”.

Reads “Unavailable” — the alpha is one click away … and the help line right here names it
Two bugs feeding each other. The train control labelled each button with that train’s latest release only, so Beta read Unavailable whenever beta.latest was empty — while beta.prerelease held a shipped alpha, and the help line beneath it said so in prose. Meanwhile the write path persisted both axes on every click, including a click on the segment already selected, so the first visit to this pane froze the install on Stable Latest. A later hand-installed alpha was then offered the last stable forever, and this screen was the one place that could have said otherwise.
