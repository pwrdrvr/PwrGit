1 Findings — the primary verb is missing from the surfaces built for browsing branches

PwrGit draws a branch name in seven places. In two of them you can move your checkout onto it; in one it is hidden behind an undocumented double‑click; in four — including the Repository refs browser, the only surface that shows all 37 local and all 34 fetched branches — the single offered verb is create a new worktree on disk. That is the most expensive answer to “put me on that branch”, and it is the only one. Specimens below are reproduced at shipped size from app.css, in PwrGit’s own font stacks.

The pattern: switching is available wherever a branch appears incidentally — on a graph row, in the title bar — and absent wherever the user went looking for a branch on purpose. Browsing is how you find the branch you cannot already see, so the browser is precisely where the verb has to be.

Switch here is the primary and the leftmost, because it is the cheap, reversible, overwhelmingly common answer. On a remote row it means what git switch already means for a bare name: create the local tracking branch and check it out — no directory, no cleanup later.

“Here” is the working target — the selected worktree, the one every other git verb in the window already aims at. When the repo owning the row holds no working target there is nothing to move, so the button is genuinely unavailable and says why rather than disappearing.

The existing slot already carries two meanings — + when the branch is free, a worktree chip when something holds it — and those answer “where does this branch live”. Switching answers “where do I go”. Folding a third meaning into one control would make the row’s only action depend on facts the reader has to reconstruct.

2 Relevance — the lists rank by tip date, which is not the same as mattering

Both lists are for-each-ref --sort=-committerdate, newest tip first. That is the right primitive and the wrong ranking: it measures when a branch last moved, not whether it is still alive or anything to do with you. The reported symptom — “a couple of local branches from months ago” — is what that ordering looks like on a repository whose local branches are mostly finished work whose remote has since been deleted.

Within a tier the arrival order is kept, so tip date still breaks every tie and nothing is re‑sorted that the ladder does not have an opinion about. The change is cheap: every input is already on LocalBranchSummary, so no new git runs and no new IPC.

Deliberately not in the ladder: authorship and branch‑name shape. “Mine” needs a per‑tip %(authoremail) probe and is wrong for any branch you inherited; demoting dependabot/* or claude/* by prefix would be a guess about a naming convention this app does not own. See 3b E for the signal that would actually carry “mine”.

3 One verb, one guard — and what is left open

Adding a verb to five more surfaces is only safe if every one of them behaves identically. Today the two existing implementations already disagree, and the busier of the two is the unguarded one.

3aThe same verb, two implementations
BehaviourguardedSwitchBranchBranchSwitcherConsequence
Uncommitted changes in the destinationCounts them, confirmsSilentgit switch succeeds when changes do not conflict and carries them over. From the title bar that happens with no notice at all — the exact scattering the guard was written to prevent.
Branch held by another worktreeReveals that worktreePrints git stderr“fatal: ‘x’ is already used by worktree at …” in a dialog footer, instead of taking you to the checkout that has it.
Destination worktree is gone from diskRefuses, names itGeneric failureNothing to switch and nothing to carry, so a confirm would be a lie either way.
Repeated activationOne at a timen/aEnter auto‑repeats while held and dialogs.ts queues rather than coalesces — the sidebar already guards this with an in‑flight flag.

Resolution: BranchSwitcher routes through guardedSwitchBranch like every other caller, and the five new controls call the same function. One code path, one confirm, one meaning for checked_out_elsewhere. The overlay keeps its own inline error line for anything that is genuinely a failure.

3bSmaller findings, and two left open
A

The decorative branch glyph announced itself

The sidebar hides ⌉ with aria-hidden; the refs browser’s three copies do not, so a screen reader reads the character before every branch name in a 71‑row table. Same glyph, same job, one of the two surfaces got it right.

B

A row’s largest target is bound to its smallest action

Single‑click on a branch name copies it. That is the least consequential thing a branch row can do, and it holds the widest hit area on the row while the primary verb had none. The collision is already visible in the code as deferForDoubleClick, which exists so that switching does not also silently replace the clipboard. Copy stays — it is genuinely useful here — but it is no longer the only thing a pointer can reach.

C

“Switch here” needs a subject, and sometimes there isn’t one

When the repository owning the row holds no working target there is no checkout to move. The control is disabled with the reason in its accessible name rather than in a title, because assistive tech reads the label over the tooltip and a disabled control still announces its name.

D

Still open: the browser’s table is not a table

.refs-table is a CSS grid of divs with a header row of bare spans, so “Branch / Upstream / Status / Last commit” are not associated with the cells under them. The obvious fix — role="table" and friends — conflicts with display:grid on the same elements, which suppresses row and cell exposure in Chromium. Doing it properly means restructuring the grid, which is more than this change should carry.

E

Still open: nothing knows which branches are yours

The strongest relevance signal available is the one nobody is reading: git’s own HEAD reflog records every checkout: moving from A to B with a timestamp, which is a true record of where this checkout has actually been. It would rank “the branch I was on yesterday” above “the branch a bot pushed an hour ago” — which tip date can never do. It is per‑worktree (each linked worktree keeps its own logs/HEAD), so folding it into a repository‑wide list is a real design question, not a sort key. Left for its own pass.
