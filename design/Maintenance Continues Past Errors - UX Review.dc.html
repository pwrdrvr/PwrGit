1cFindings
1

Keep the behaviour

Per-repository review and delete failures no longer cancel later, independent work. Cancellation and a command that returns nothing still stop. Every branch safety check is unchanged. This part ships as is.

2

A second error style in one dialog

The Worktrees step reports failures with the shared outcome card (6% danger wash, mark, count headline, one row per object). #528 adds .maintenance__issues: a full --danger-soft fill, a red “Needs attention” label and no mark. Two failures in one run would draw in two styles.

3

The headline names nothing

Copy rule 1 is count + object + what happened: “1 branch wasn’t deleted”. “Needs attention” says neither how many nor of what.

4

Prose set as log output, and a repeated sentence

Reasons are 11 px mono, joined with newlines under a repository heading. The first line, “26 local branches deleted; 1 retained.”, repeats the receipt. Rows should be repo · branch with the tip SHA, so a failure matches the receipt row, and the reason in sans with its lead phrase in danger ink.

5

“1 needs attention” counts repositories, not branches

With 27 retained branches in one repository, the step line still reads 1 needs attention. Count the branches instead: “0 deleted · 27 not deleted”. A failed review counts repositories: “1 not reviewed”.

6

The scroller has no focus ring

The list takes Tab focus (tabIndex 0) so the keyboard can scroll it, but nothing draws when it has focus. House rule: outline: 2px var(--focus-ring).

2Recommended: each step reports with the outcome card, in step order, above the receipt

Same behaviour as #528. Only the drawing changes. Each step that left something behind gets one MaintenanceProblem card (Removal Errors 5a–5c): Local branches first, then Garbage collection. A card's rows scroll inside it once there are more than four, so the head always says how many and the receipt stays in reach. The cards appear as soon as a step finishes and stay while later steps run.

PieceChange
Issue modelStepResult.issues becomes rows, not joined text: { repo, path, branch?, head?, reason, raw? }. A retained branch is one row; a repository failure with no branch rows is one row. The repository summary sentence is not a row.
CardBranch and GC issues render as .maintenance__problem (head with mark, headline, sub; one .maintenance__problem-row per issue). Lift the worktree panel’s Icon and Reason so both panels share them. Delete .maintenance__issues and its CSS.
HeadlinesBranches: “1 branch wasn’t deleted” / “N branches weren’t deleted”; review only: “Local branches couldn’t be reviewed in N repositories”; mixed: “Local branches: N problems in R repositories”. GC: “Garbage collection failed in N repositories”.
ReasonLead phrase = main’s first sentence, in danger ink. Raw Git text (starts error:/fatal:/warning:, or multi-line) → “Git refused to delete it” with Details holding the text.
ScrollingThe row list scrolls at max-height: 196px, takes tabIndex 0 with an aria-label, and draws outline: 2px solid var(--focus-ring) on :focus-visible.
Step linesCount objects, not repositories: “· N not deleted”, “· N not reviewed”, “· N failed”.
PlacementAbove the receipt steps when done; under the live status card while a later step runs. Cards in step order.
