1Findings: the list keeps everything you opened, so the distance to any repository is whatever you opened above it

The operator, on the sidebar: “It's great because I can scroll through and find what I want and expand/collapse the sections I want and don't have to wait for a sub‑list to load or lose my expand/collapse status as I switch between repos. But it sucks because it's too much non‑deterministic scroll length to find a specific repo.” Both halves are the same property: per‑repo expand state persists, and a repository's position in the scroll is the sum of every block above it. Specimens are drawn at shipped size from styles/app.css in the light theme; every repository name is invented.

Collapsed, a repository is one 26px row. Open with its five section heads closed it is about 150px; with Worktrees open (six rows, a ghost, the Finished line) about 330px. The sticky header tells you which block you are inside; nothing on screen tells you where any other block is.

1bFour findings
1

The scroll distance is a function of history, not of the list

The repository order is stable (the lens and the folder groups decide it), but the pixels between you and a repository depend on what you opened earlier. So scroll memory never forms: the same flick lands somewhere different every day.

2

The sticky header answers “where am I”, never “where is X”

.repo-row is position: sticky, so the block you are in stays named. Every other repository is either off screen or a 26px row between two tall blocks. With 26 to 60 repositories that is most of them.

3

⌘F is the “I know the name” path, and it changes the selection

Jump to repo… is deterministic, but a pick selects a worktree, which moves the main pane and records a focus visit. That is right when you are going somewhere. It is the wrong tool for “show me what's in harbor's branches” while the graph stays where it is.

✓

The cure must not collapse anything

Collapse‑all, or a one‑open accordion, makes the distances small by deleting the state the operator values. NN/g says the same about desktop accordions: let several stay open. The fix is a map beside the list, not a smaller list.

2Prior art: who keeps many expanded sections in one scroll, and how they navigate it

None of the multi‑repo Git clients (Fork, Tower, GitKraken, Sublime Merge, GitHub Desktop, SourceTree) put many expanded repositories in one scrolling tree. They split it into a repository manager or switcher, plus one repository per tab or window, with a fuzzy quick‑open. PwrGit's single tree is the unusual part, and it is the part the operator likes. So the useful precedents come from long documents and code trees.

43a in detail: the fit ladder, the jump, and the rules

The tree is designed to work at 240px; that is the sidebar's own floor (useColumnResize(…, 320, 240, 520)). The index only ever spends width the tree does not need, so the tree never drops below the width it is already built for.

4aThe fit ladder: measured, not a breakpoint
SidebarIndexNamesRule
≥ 240 + naturalits natural widthwholewidth: max-content: the longest name in the lens plus the item's padding. At 430px with these names that is 107px; the tree keeps 322px.
240 + min … 240 + naturalsidebar − 240ellipsizeEvery pixel past the floor. The full name is on a hover card, drawn only for a name that is actually cut. At the 320px default: 80px.
< 240 + minhidden—min is calc(7ch + 19px) in the index's own 12px font, measured from a hidden probe that carries the same rule: 76px in the built sidebar, so it appears at 316px. Below that, the Display options item says why it is off.
Anyhidden—Fewer than two repositories in the lens, or turned off in Display options (remembered).

Seven characters is the shortest truncation that still tells a family apart (kestrel, juniper, PwrSuit…). Everything follows the type axis: the font is calc(--sidebar-title-size − 1px), so ch, the natural width and the fit all move with it. The tree's narrow‑width rules (the 260px ghost‑tag step) now ask the tree's own column, so they fire on the tree's width rather than the sidebar's.

EventBehaviourWhy
Click or Enter on an index itemOpens + scrollsHeader to the top of the scrollport, instantly (long distances smooth‑scrolled are slow and sweep the highlight through every repo in between). The repository opens if it was closed, with the lazy badge fill a manual expand does.

4dKeyboard and accessibility
✓

A labelled nav, not part of the tree

nav aria-label="Repository index", a list per folder group named by the folder, buttons inside. The tree stays role="tree" owning only treeitems and groups. The spy item carries aria-current="location"; each button aria-controls the tree.

✓

One tab stop, arrows inside

↑/↓ walk the names, Home/End jump to the ends, typing a few letters moves to the next name that starts with them, Enter or Space jumps. Tab order: lens, index, tree.

✓

The house focus ring

outline: 2px solid var(--focus-ring), inset like the tree's rows because the items sit flush. The current marker is a 2px accent rail plus a tint, so it survives forced colours and reads at 3:1 without the tint.
