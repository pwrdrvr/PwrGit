0Brief — the rebase checkbox column costs every row its width and is almost never used

Harold, 2026-11-14: “this checkbox that only shows on mouse over is taking this entire column and chopping off the train lines.” Every lineage row reserves an 18px box plus an 8px gap between the lane gutter and the SHA, visible only on hover. In a narrow main pane the gutter is the first thing that gives way, so the lanes are clipped to make room for a control that is invisible. The wager is that no one has ever selected commits for a rebase this way. Goal: remove the reserved column and keep Squash, Reorder and Tidy reachable, ideally more directly than today. Open decision for review: 2a (start the edit from a commit’s context menu) is recommended and built in the PR that goes with this board; 2b–2d are recorded as rejected.

1As built — a hover-only box, a free selection, and a backend that accepts one shape

The row’s gutter is capped at clamp(16px, 100cqi − 230px − 14ch, 160px); the 230px budgets the checkbox, the SHA chip and the age. The checkbox is the only way to select commits. The selection bar then offers Squash, Reorder, Tidy and “Open rebase tool”.

1bFindings
1

26px on every row, at every width

18px box + 8px gap. Below a ~515px pane the gutter is what shrinks, so lanes are clipped first; above it the subject loses the 26px instead. The box is drawn even while invisible.

2

Nothing leads to it

It appears only under the pointer. The context menu, the commit card and the Rebase tab do not mention it; the tab’s empty state says “Select commits in the graph” without saying how.

3

Free selection, one accepted shape

Main’s validateSelection accepts only the N most recent commits, contiguous, including HEAD, with at least two. Any other set of boxes is refused (“Select a contiguous run of the most recent commits”) after you pick an operation. The real choice is one commit: where the run starts.

4

Four steps for one decision

Tick the HEAD row, tick each row down to the start, click Squash in the selection bar, then read the rail. Ticking rows on another lane is allowed and always fails.

2Options — choose the start commit, not a set of commits

Every option removes the reserved column. They differ in how the start commit is chosen. The range always ends at HEAD, so one choice is enough.

The heading names what all three do; each entry names the count, so the reader sees the range before choosing. Choosing selects HEAD down to this commit (rows tinted), opens the rail’s Rebase tab on that operation, and shows the selection bar so the operation can still be switched or cleared. Tidy appears only where AI history editing is on. Never offered on the HEAD row (one commit) or on a commit HEAD does not reach. Disabled with the reason when a merge sits in the run or the run reaches the repository’s first commit.

2bRejected. Float the box over the row on hover

No reserved width, but still invisible until hovered, and it sits on the SHA chip, whose hover opens the commit card. Keeps the free selection that main mostly refuses (1b ③).

2cRejected for now. ⇧-click a row to set the start

Zero chrome, but nothing on screen says it exists, and a plain click already opens the commit. Worth adding later as an accelerator once a range exists (⇧-click moves its start).

2dRejected. A “Choose commits” mode in the Rebase tab

Shows the column only while the mode is on. Discoverable from the tab, but the column comes back exactly when the lanes matter most, and it is a mode to leave.

3As built in the PR — 2a, with the 26px returned to the gutter

The gutter cap becomes clamp(16px, 100cqi − 204px − 14ch, 160px) (the lane scrollbar carries the same expression). The selection bar and the Rebase tab are unchanged apart from the tab’s empty-state text.

3eWhy a warning, not hiding the entries
1

One click made rewriting shared history easy

The checkbox needed one tick per commit; the menu offers “Squash 120 commits into one…” on any row of a pushed main. Code review on PR #600 flagged it.

2

Warn once, under the heading

“Pushed” is Git’s own test: reachable from any remote-tracking ref (rev-list HEAD --not --remotes, computed with the lanes, no Git call per right-click). The sentence sits under the group’s heading, in the warning tone, and is every entry’s accessible description, so it is said once and read with each.

3

Still offered

Nothing changes for anyone else until a force push, and tidying commits already pushed to your own feature branch is common. Hiding would remove a legitimate edit to stop an unlikely one; the dry run and Apply still stand between the click and the worktree.
