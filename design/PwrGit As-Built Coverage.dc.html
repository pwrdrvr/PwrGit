PwrGit · as-built coverage

What ships, and where it is drawn

The companion to PwrGit App Baseline. Three things live here: every place the retired 2026-08 wireframe disagreed with the shipped app, a surface-by-surface map of what the design project actually covers — so a gap reads as a gap rather than as a screen nobody built — and the artboards, or turns of them, that draw something which has not shipped, so a proposal is not read as a record.

3 · Drawn, not shipped

Everything in section 2 ships. These artboards, or these turns of them, draw something that does not — a proposal still under review, an option not taken up, or a question left open. Read them as design, not as a record of the app.

ArtboardStatusWhat is not built
Agent History Editing — UX Reviewwhole artboardA review of PwrGit#149, which is still open, and a counter-proposal to it: the agent proposes a history, PwrGit proves the result leaves the code byte-for-byte identical and replays cleanly, and you apply it. Its ✦ Tidy action, agent-written squash messages, and the Settings › AI Providers and AI Features pages are all unbuilt; nothing in the renderer references them, and section 1’s “no model is wired into PwrGit” still holds.
Git Runtime Settings — UX Reviewturns 2–3The redraw and the state table. Turn 1 is the card as built in PwrGit#296.
Palette Kind Glyphs — UX Reviewturns 3–4The worktree redraws and the remote-branch mark. PwrGit#289 shipped the labels and says outright that no glyph is redrawn.
Forge Hosts — UX Reviewturn 3Signing in without a CLI. Drawn only so the host row leaves room for a second credential source; the artboard itself calls it “not this change”.
Branch Switching and Ref Relevance — UX Reviewcard 3b, D–EThe two items it leaves open: the refs browser’s grid, which is still not an accessible table, and a list ranked by the HEAD reflog. PwrGit#255 names the reflog as the signal that would carry “mine”, and leaves it to 3b·E because the reflog is per-worktree.
