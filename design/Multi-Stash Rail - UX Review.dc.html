2 The tab strip — three ways to fit, and the one taken

The labels, three counts and › need about 214 px before any padding, and a 280 px rail leaves 255 inside its bar padding. So some rule has to decide what gives way at the minimum. The options below all keep today’s type size.

2aTighten padding only
Changes4Stashes4Rebase2›

Twelve pixels of padding back, but the bar still has no rule for what gives way, so it only moves the width at which the button falls off. At 280 it is still 65 px outside, as drawn. Not enough.

2bRaise the rail minimum to 330 px
Changes4Stashes4Rebase2›

A one‑number change in useColumnResize. It takes 50 px from everyone who dragged the rail narrow on purpose, which is unrelated to stashes. At 330 with a rebase selection it is still 15 px over, as drawn, so the minimum would have to climb further. Rejected.

2cTabs shrink, counts and › don’t · compact under 330 — shipped
Changes4Stashes4Rebase2›

A container query on the rail makes the bar denser as the rail narrows, and min-width: 0 gives it a last resort. Inactive labels ellipsize, and the counts, the active tab and the collapse button never do. In Geist the last resort is not reached anywhere from 280 to 420 px. On a platform fallback face it degrades to a shortened label, not a missing button.

3 Behaviour behind the pixels

Found reading the code beside the renders. The first changes what a click does; the rest change what a keyboard, a screen reader or a hover gets.

A

View patch did nothing with file details open

The branch predates File history/Blame. Every other diff opener clears fileInsightTarget first, and DiffPane stays hidden while one is set. Stash’s opener didn’t, so the patch loaded behind the pane you were looking at. It clears it now.

B

In flight is aria-disabled, not disabled

Every action button went disabled while any command ran. Chromium blurs a control the moment it is disabled, so pressing Apply from the keyboard threw focus to <body> for the length of the Git call. That is the house rule in styles/AGENTS.md. Handlers now refuse a second command instead.

C

A disabled Pop/Drop says why on hover

For a stash object that occurs twice in the reflog, Pop and Drop are genuinely unavailable. That is the .lens-chip.is-empty case: aria-disabled plus a guarded click, so the house hoverTooltip can still explain. Native title tooltips are gone throughout. The destination line under the actions says “Apply restores into” there, not “Apply and Pop”.

D

Focus rings on every new control

The row toggle, the four actions and the submit button had no :focus-visible rule and fell back to the browser’s. They now paint outline: 2px solid var(--focus-ring), inset on the toggle because the card clips its overflow.

E

Built from the Changes tab’s parts

The eyebrow is .changes-section__label, the field and submit are .commit-input/.commit-btn, the paths are .file-path, and the mark is .ref-section__chev. Two tabs side by side should not differ in type scale because two people wrote them.

F

Contrast holds in both themes

Measured on the open (hovered) row, the worst case: the recovery chip is 6.22:1 dark and 4.84:1 light, and the neutral count is 5.21/5.17. The meta line, age, scope note and destination line are all 5.05 or better at 10 px.

?

Open: the patch’s per‑file menu at a stash

A stash patch reuses the commit menu (File history, Blame, View file at this commit) against the stash’s W commit. Untracked files live in its third parent, not in W’s tree, so those entries can open onto nothing. That needs a backend answer, not a CSS one, so it is left for the author.

?

Open: must a stash have a name?

git stash never asks for one, but the button stays unavailable until you type. That is defensible, because a named stack is the point of the feature, and it matches how the commit box treats its summary. It is still a product call, so it is flagged rather than changed.
