1As built: Clone never offers a fork, and Fork… still wants a second copy

Two dialogs, two gaps. Clone picks a repository you can't push to, marks it read-only, and clones it anyway. It never asks the forge whether you already have a fork, and never offers to make one. Fork…, opened on a checkout that is already on disk, offers "Fork in place…" as a side door. The primary button still says Fork & clone, and the dialog still asks how and where to clone a second copy. Names are contrived: octo-labs/sparkline is the source, riverbend is the signed-in account, lumen-co is an org.

32a in every state the forge can answer

Picking a forge repository runs one repo:forkPreflight for the default account. Its answer sets the fork card's pill, the default choice, and the submit label. Defaults: the original, unless you can't push and a fork of yours already exists. Creating a repository on your account is never a default. Repositories you own skip the pair, since preflight answers self_owned. So do local-path sources, which have nothing to fork.

4Fork… on a checkout that's already here: the button becomes Fork in place

When the dialog is seeded from a local checkout and the source is still that repository, nothing needs cloning. The dialog switches to in-place mode itself, with no hand-off to a second dialog. It asks repo:forkCheckoutPreflight instead of repo:forkPreflight, and the answer is a superset. Clone with and Check out to give way to the Afterwards remote plan that ForkCheckoutDialog already draws. Submit runs repo:forkCheckout. "Clone a separate copy instead" stays as a quiet link for the rare case.
