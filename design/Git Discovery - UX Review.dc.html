Git discovery — hooks, excludes, and the rest of the iceberg

Git already has answers to problems PwrGit users hit every week — a personal folder that keeps showing up as untracked, a commit that silently will not land, a conflict resolved for the third time. Most people never learn those answers exist, because Git keeps them in files nobody opens. This board designs one discovery system: Git speaks up only at the moment it has done something, every surface names the file and the scope, and the inventory lives one click away instead of in the main path. Turns 1–2 are the diagnosis and the system; 3 is hooks, 4 is ignore rules and .git/info/exclude, 5 is everything else Git can do that people should use and do not. Nothing here is built. Repository names, paths and output are invented.

1 Findings — Git does things PwrGit never mentions

Read against main @ 3301600. PwrGit runs real git commit and git push through dugite with no --no-verify, so every hook a repository carries fires on every commit and push. It writes exactly one kind of ignore rule. It reads a dozen config keys and suggests none. None of that is wrong — it is just invisible, and the one place it surfaces is when it breaks.

1aSix findings
1

A hook that rejects a commit makes the Commit button do nothing

commitChanges returns commit_failed carrying the hook's stderr (git-service.ts:421), and ChangesTab.commit only handles r.ok (ChangesTab.tsx:506). A failing pre-commit or commit-msg therefore produces no toast, no message, no output — the draft stays, the files stay staged, and the only trace is the Logs window. This is the most common hook interaction there is. Every other rail action in the same file toasts its failure.

2

Hooks run on every commit and push, and nothing says they exist

The only mention anywhere is the confirm before --continue in OperationBanner.tsx:47 — "Git hooks may run" — which warns without saying which. A 40 s pre-push test suite reads as a hung push.

3

A shadowed hooks directory fails silently, and it is common

When core.hooksPath is set — Husky v9 sets it to .husky/_ — Git stops reading .git/hooks entirely. Git LFS installed its pre-push there, so LFS objects stop uploading on push, with no error from anyone. PwrGit already checks filter.lfs.* for its LFS chip; it never checks whether LFS's hooks can run.

4

Ignore has one destination, and it is the shared one

The untracked-row menu offers Add to .gitignore and nothing else (changes-row-menu.ts:82). That file is committed. The personal cases — .local/, scratch notes, an editor or agent folder — belong in .git/info/exclude (this clone, every worktree, never committed) or the global core.excludesFile. Offered one door, people either commit their personal patterns into the team's file or live with a permanently dirty worktree.

5

Nothing explains why a file is missing

A file matched by the global excludes file never appears in Changes, and there is no way to ask why. git check-ignore -v answers exactly that — source file, line, pattern — and nothing calls it.

6

There is no help primitive to build discovery from

The renderer has twelve bespoke empty states, two notices and a keyboard-help panel, and no generic tip, receipt or explain popover. Discovery built surface-by-surface would be twenty inventions. 2b is one.

2 The system — speak when Git acts, name the file, stay out of the way

Self-documenting means the UI teaches Git while you use it: the words on screen are Git's own words, pointed at Git's own files. The goal is not a tutorial or a tips carousel. It is that someone who uses PwrGit for a month could open a terminal and do the same thing by hand, because every surface showed them the file and the command.

3 Hooks — say which ran, say why one refused, draw where they fire

PwrGit does not need to guess which hooks ran. Running the commit with GIT_TRACE2_EVENT pointed at a pipe yields a child_start event with "child_class":"hook" and hook_name for each hook, and a child_exit with its exit code and elapsed time. That is the whole data source for 3a. Fixture: orbit-deploy, three worktrees, Husky for pre-commit and commit-msg, Git LFS installed.

4 Ignore rules — three files, three audiences, one decision at the moment you make it

Git reads ignore patterns from three places, in this precedence: every .gitignore in the tree (committed, shared), then $GIT_COMMON_DIR/info/exclude (this clone, shared by all its worktrees, never committed), then the file named by core.excludesFile, default ~/.config/git/ignore (every repository on this machine). The second one is the answer to "stop showing me my .local/ folder in every worktree" — and almost nobody knows it is there.

5 Everything else — Git features people should use, each tied to the moment it helps

The test for every row: is there a moment when Git has just done the expensive thing the feature would have saved? If yes, that moment gets an L0 line, and the feature's switch lives in the setup sheet or Settings. If there is no such moment, it does not get a surface — which is why git notes and sparse-checkout are near the bottom.
